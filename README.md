# Noxen

Drone frames whose printed parts are generated by a topology engine, one script per part, every optimisation run on GitHub.
The picture below is the current assembly, redrawn by CI after every result; nothing here is updated by hand.

## How it works
One script per part, GitHub runs the topology engine, one page shows the assembly. Claude writes scripts, nothing else.

## Every part
1. Tell the design chat what the part mounts and carries. It writes your notes to `parts/<name>/feedback.md` and starts a worker
   session for the stream (CLAUDE.md, Sessions), so the chat stays free.
2. The worker writes `parts/<name>/part.py` and a line in `systems/<drone>.assembly.json`, pushes to main (the push starts the run).
3. The runner optimises, solid-checks, commits `result.json` + `part.stl`. The page rebuilds; the grey box becomes the real part.
4. The worker fixes fails at the root cause, republishes the artifact, reports once to the design chat and archives itself.

Manual run of any part(s): Actions -> parts -> Run workflow -> names. Empty = everything missing or stale.
Housekeeping: a weekly scheduled session runs `tools/sweep.py` on Monday morning and archives finished sessions.

## What the runner does when it is cut off
Runner cap is 6 h. The engine checkpoints every 10 iterations; a job that hits the cap saves the checkpoint and
starts itself again for that part, up to 4 attempts (about 22 h). A crash is not retried: it shows red and needs a fix.

## Layout
```
topo/                  engine (from nox/topo; the setup audit, PCTG and the export cleanup added here)
tools/solid_check.py   the gate      tools/build_site.py  page builder      tools/stale_parts.py   tools/sweep.py  housekeeping
parts/<name>/part.py   the setup; CI adds result.json, part.stl, preview.png
systems/*.assembly.json  every drone: part ids, placeholder shapes, poses       systems/dimensions.md  the numbers
site/index.html        the viewer (three.js, reads site/assembly.json that CI writes)
archive/               meshes nothing uses any more (archive/README.md)
```
Status on the page is computed, never stored: `result.json` present and its `part_sha` matches `part.py` -> done or failed; mismatch -> stale; missing -> pending.
